# 代码架构

## 1. 主控 STM32 工程

### Core
CubeMX 生成的外设初始化代码，主要负责 GPIO、TIM、ADC、USART 等基础配置。一般不直接写业务逻辑，避免后续重新生成工程时覆盖手写代码。

### Hardware
面向硬件模块的驱动层：

- `TRACK`：八路红外巡线传感器，输出黑线掩码、偏差和有效探头数量。
- `ENCODER`：读取左右轮编码器计数，用于直行同步和避障转角/距离闭环。
- `CAMERA`：解析 OpenMV 通过 USART1 发送的 `$O,...#` 数据包，并做在线/连续帧确认。
- `ULTRASONIC`：HC-SR04 触发、回波计时、距离换算、慢速/停车判断。
- `OLED`：显示运行状态、时间、巡线偏差和避障状态。
- `LED/KEY/IIC/PSTWO/STMFLASH`：保留当前工程依赖的外设支持代码。

### BALANCE/CONTROL
项目核心控制层：

- `control.h`：集中放置速度、巡线、避障、起点停车等参数。
- `control.c`：实现模式选择、PWM 输出、巡线 PD、编码器同步、视觉+超声波避障状态机、OLED 状态显示。

主循环的核心流程：

```text
初始化外设
↓
PB8 选择 LOW/HIGH 模式
↓
周期控制：读超声波、读编码器、读巡线
↓
若超声波距离进入触发范围且 OpenMV 连续确认障碍：执行梯形避障
否则：执行巡线 PD + 编码器同步
↓
检测起点宽黑线，满足条件后停车
```

## 2. OpenMV 脚本

`openmv/main.py` 完成图像侧预处理和障碍候选筛选：

1. QQVGA RGB565 采集。
2. 底部 `LINE_ROI` 检测正常黑线宽度。
3. 上方 `OBSTACLE_BANDS` 分层检测：
   - 暗色障碍：与同一高度下的预期黑线宽度比较，明显更宽才认为是障碍；
   - 橙色/彩色障碍：用 LAB 阈值、面积、填充率和尺寸过滤。
4. 选择分数最高的候选障碍。
5. 每 50 ms 通过 UART3 输出：`$O,valid,zone,cx,cy,w,h,area,dist_cm,band,line_w,exp_w,type,fps#`。

## 3. 数据接口

OpenMV 只负责告诉 STM32“是否看到障碍、障碍大概在哪、图像上有多大”。STM32 不直接相信单帧视觉结果，而是结合：

- 摄像头在线；
- 连续帧确认；
- HC-SR04 距离达到触发阈值；
- 18 cm 安全停车阈值。

这样把“识别”和“安全距离”分离，降低误检或漏检造成的风险。
