# 方法说明与方案取舍

## 为什么采用“OpenMV 视觉确认 + HC-SR04 距离触发”

单独用超声波可以判断前方距离，但它不能可靠区分障碍物在左、中、右哪个方向，也容易受安装角度、反射面形状影响。单独用 OpenMV 可以看到障碍物位置和大小，但视觉距离估计受光照、阈值、颜色和摄像头姿态影响较大。

因此当前方案让两者分工：

- **OpenMV**：确认是否存在障碍，并判断障碍偏左、居中或偏右；
- **HC-SR04**：给出更可靠的近距离安全判断；
- **STM32**：只有在距离进入触发范围且视觉连续确认时才绕障，若距离过近则无条件停车。

这样比单传感器方案更稳，也更适合当前已经能巡线的小车平台。

## 为什么不用纯固定延时避障

早期方案用固定 PWM + 固定延时完成转向和回正，问题是：

1. 电池电压变化会导致同样延时下转角不同；
2. 左右电机动力不一致，左右绕障幅度差异明显；
3. 地面摩擦、褶皱、轮胎打滑会让路径重复性变差。

当前代码把关键的转向角度和斜向离开距离改为编码器计数控制，只保留超时作为保护，因此每次绕障路径更一致。

## 为什么不用 OpenMV 同时巡线

OpenMV 曾探索过巡线+避障一体输出，但实际问题是：

- 摄像头视角、曝光和阈值会同时影响黑线与障碍识别；
- 图像巡线延迟比 IO 巡线更明显；
- 当前八路红外传感器已经能提供足够快、足够稳定的巡线偏差。

所以最终采用“八路 IO 巡线 + OpenMV 只做障碍确认”的结构。这样主控巡线实时性更好，OpenMV 参数调试也更独立。

## 为什么用分层宽度法识别暗色障碍

黑色障碍和黑线颜色接近，如果只按黑色阈值找 blob，容易把赛道黑线误认为障碍。当前 OpenMV 脚本先在底部估计正常黑线宽度，再根据透视关系估算上方同高度黑线应有多宽；只有当暗色 blob 明显宽于预期黑线，同时满足高度、面积和填充率要求时，才当作障碍。

该方法的优点：

- 不依赖复杂模型，OpenMV 能实时运行；
- 能减少把普通黑线当成障碍的误判；
- 参数直观，便于现场调试。

不足是仍然依赖阈值和光照，环境变化较大时需要重新调 `BLACK_THRESHOLDS` 和 ROI。

## 其他探索方案的问题

- **仅靠颜色阈值**：对橙色等彩色障碍有效，但对黑色/暗色障碍容易与黑线混淆。
- **仅靠超声波停车**：能避免撞上，但无法绕行，也不能判断从哪侧绕。
- **OpenMV 估距直接触发**：图像中的 `cy` 与实际距离不是线性稳定关系，摄像头角度稍变就会偏差明显。
- **固定时间绕障**：实现简单，但路径重复性差，左右绕行不对称。

## 左右绕障独立参数

由于实际小车的左右电机、轮胎摩擦、重心和传感器安装不完全对称，不能假设“向左绕”和“向右绕”使用完全相同的路径参数。当前代码已保留向右绕障参数不变，并给向左绕障增加独立修正：

- `AVOID_LEFT_EXIT_SCALE_X100`：向左绕时的斜向离开距离比例，当前为 90%，避免离轨道过远；
- `AVOID_LEFT_BACK_TURN_SCALE_X100`：向左绕后转回轨道的角度比例，当前为 115%，让车更积极地切回黑线；
- `AVOID_LEFT_RETURN_TIMEOUT_MS`：向左绕后继续弧线找线的最长时间，当前为 2500 ms。

如果向左绕仍然找不到轨道，优先继续增大 `AVOID_LEFT_BACK_TURN_SCALE_X100` 或 `AVOID_LEFT_RETURN_TIMEOUT_MS`；如果向左绕会蹭右侧障碍，再增大 `AVOID_LEFT_EXIT_SCALE_X100`。

## 当前可调参数建议

- 避障触发距离：`AVOID_START_DISTANCE_CM`。
- 近距离安全停车：`ULTRASONIC_STOP_DISTANCE_CM`（在 `ultrasonic.h`）。
- 绕障转角：`AVOID_LARGE/MID/SMALL_TURN_TARGET`。
- 斜向离开距离：`AVOID_LARGE/MID/SMALL_EXIT_ENCODER_TARGET`。
- 平行通过时间：`AVOID_LARGE/MID/SMALL_PASS_MS`。
- OpenMV 暗色阈值：`BLACK_THRESHOLDS`。
- OpenMV 彩色障碍阈值：`ORANGE_THRESHOLDS`。

调参建议每次只改一类参数，并记录测试现象：先保证识别稳定，再调避障距离和转角，最后调高速巡线参数。
